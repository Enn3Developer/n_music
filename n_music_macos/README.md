# N Music for macOS

The native Mac app: SwiftUI and AppKit over the same Rust core as the other apps, through
`n_music_ffi` (a static library and its UniFFI Swift bindings). It has the Qt desktop app's
pages, flows and wording, built from the Mac's own controls, and reads the Qt app's translation
files (`n_music_desktop/assets/lang`) with the same keys.

Requires macOS 14 or later on Apple silicon.

## What is Mac-specific

- **Core Audio output.** The core plays through an AUHAL unit on the chosen or the default
  device (`n_music_core/src/audio/output/backend/coreaudio`), not through cpal:
  - **Sample-rate matching**: the device is switched to the rate of what plays, or its smallest
    whole multiple the device has, so nothing is resampled (Settings › Playback, "Match the
    output's sample rate"). A device that refuses a rate keeps its own and is not asked again.
  - A 10 ms I/O buffer, 40 ms when the core is asked to save power (its `offload` option), so
    the processor wakes less often.
  - The unit stops while paused; device changes (default device, unplugged headphones) are
    followed through the HAL's property listeners, not by polling.
- **Now Playing and media keys.** `MPNowPlayingInfoCenter` and `MPRemoteCommandCenter`: Control
  Center, the media keys, AirPods and the Touch Bar. The info is set again only on
  discontinuities (a new track or cover, play/pause, a seek), never for each position report.
- **Power.** The app tells the core when none of its windows is on screen, so it stops sending
  positions and the clocks stop redrawing. It holds a `ProcessInfo` activity only while playing,
  so App Nap applies otherwise. Nothing runs on a timer while idle.
- **Covers.** Decoded off the main thread by ImageIO (`CGImageSourceCreateThumbnailAtIndex`) at
  the size they are shown at, never at full size, and kept in an `NSCache` bounded by decoded
  bytes.
- **Build flags.** Release builds the core with Cargo's `[profile.macos]` (the release profile
  with `opt-level = 3`, fat LTO and one codegen unit) and `-C target-cpu=apple-m1`; Swift with
  `-O`, whole-module optimization and dead-code stripping.

## Building

You need:

- Xcode 16 or later (Swift 6),
- Rust through [rustup](https://rustup.rs) (the build adds the `aarch64-apple-darwin` target if
  it is missing),
- CMake, which the Opus library's build uses: `brew install cmake`.

Open `NMusic.xcodeproj` in Xcode and run the NMusic scheme, or build from the terminal:

```shell
cd n_music_macos
xcodebuild -project NMusic.xcodeproj -scheme NMusic -configuration Release \
  -derivedDataPath ../target/xcode build
open "../target/xcode/Build/Products/Release/N Music.app"
```

Before compiling the Swift code, Xcode runs `scripts/build-core.sh`, which builds `n_music_ffi`
as a static library into `target/macos/<profile>` and generates its Swift bindings into
`Generated/` (not committed). Debug builds use Cargo's `dev` profile, which builds quickly;
Release uses `[profile.macos]`, which takes several minutes. `N_MUSIC_RUST_PROFILE=macos` makes
a Debug build use the optimized core too. The script also runs on its own:
`scripts/build-core.sh [debug|macos]`.

### Telegram

As for the other apps, signing in to Telegram needs N Music's API credentials when building
(see the [main README](../README.md#telegram)). Set them in the environment Xcode or
`xcodebuild` runs in:

```shell
N_MUSIC_TELEGRAM_API_ID=12345 N_MUSIC_TELEGRAM_API_HASH=0123456789abcdef \
  xcodebuild -project NMusic.xcodeproj -scheme NMusic -configuration Release build
```

Without them the app builds and runs with the Telegram source turned off.

### The Xcode project

`NMusic.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
`project.yml`, and committed so the app builds without XcodeGen. After adding, removing or
moving files, or changing a build setting, edit `project.yml` and regenerate the project:

```shell
brew install xcodegen
cd n_music_macos
xcodegen < /dev/null
```

Changes made to the project in Xcode itself are lost the next time it is generated.

## Releases

Each release has `N-Music-<version>-macos-arm64.dmg` and the same app in a `.zip`, built by the
`macos` job of `.github/workflows/release.yml`.

The app is signed ad hoc, not with a Developer ID, and not notarized, so Gatekeeper blocks it
the first time it opens. On macOS 15 and later, the Control-click › Open bypass no longer works.
Either:

- try to open the app once, then go to System Settings › Privacy & Security, find the message
  about N Music, and click **Open Anyway**; or
- remove the quarantine attribute after copying the app to Applications:

  ```shell
  xattr -dr com.apple.quarantine "/Applications/N Music.app"
  ```
